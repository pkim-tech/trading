# Trading Alpha Engine

## Session Commands
- `go` — session start: read the first ~60 lines of `docs/session_cache.md` and the full `docs/backlog_cache.md`, and give a brief summary of where we left off, what's next, and any current backlog items worth flagging.
- `session close` — session end: write the session summary entry (starting with `## <date> — <title>`, no surrounding `---`) to a file and run `python scripts/session_cache_update.py <file>` (or pipe via stdin) — this mechanically prepends to `docs/session_cache.md` (cap 10, drop oldest, gitignored) and appends to `docs/conversation_summary.md` (permanent, uncapped, committed) in one shot, no need to read either file first. Commit only `docs/conversation_summary.md`. No tests, no skills.
- `feature wrap` — mid-session feature complete: update relevant docs, review pre-commit checklist (`docs/pre_commit_checklist.md`) manually, and commit. Does not trigger session close. **Do not invoke any skills (especially verify) during this command.**
- `session wrap` — in order: (1) update relevant docs, (2) review pre-commit checklist manually, (3) write the session summary entry via `python scripts/session_cache_update.py` (see `session close` above) to update both `docs/session_cache.md` and `docs/conversation_summary.md`, (4) commit everything including both files. **Do not invoke any skills.**

## Research Log
`docs/research_log.md` (permanent, committed, append-only) is a lab notebook of real experiments run against this system — hypothesis, method, result, verdict, follow-up — distinct from `docs/backlog_cache.md` (current, actively-trimmed pointer list of active items, read in full every session start) and `docs/deep_backlog.md` (permanent full-detail archive of every backlog item, resolved or not — resolved items are kept in place and marked ✅, never deleted) and `docs/conversation_summary.md` (session narrative). Append an entry to the research log directly (no capping/pruning logic, no wrapper script needed — a plain append) whenever a real experiment produces a finding, whether or not it also produces code changes or a backlog item — don't wait for session close. When a backlog item is resolved: (1) add or update its full-detail entry in `docs/deep_backlog.md` (marked ✅, matching that file's existing style) so it's never lost, (2) if the resolution is mostly research narrative (hypothesis/method/result) rather than an action record, also write a `docs/research_log.md` entry and have the `deep_backlog.md` entry point to it instead of duplicating the writeup, and (3) shrink the `docs/backlog_cache.md` entry to a one-line pointer at `docs/deep_backlog.md` (and/or `docs/research_log.md`).

## Project Overview
A z-score mean reversion backtesting and optimization system targeting leveraged ETFs. Runs parallel grid sweeps over take profit, stop loss, and hold time parameters to find optimal strategy configurations with positive alpha vs SPY. Now in live trading phase with manual execution via Schwab.

- `scripts/run_v4_backfill_sweep.sh` — v4 kernel-correctness backfill wrapper (fill-optimism resolution bounds, `fixed_sl` sweep, Open-check entry timing — see `docs/backlog_cache.md`). `backtester._simulate_trail_both` now computes three parallel trailing-buy bounce-fill resolutions per node, since none of hourly OHLC proves the true intrabar path: **possible** (existing/unchanged, assumes Low-before-High), **pessimistic** (new, mirror-image Low-after-High assumption — always same-bar-or-later and same-or-worse price than `possible`, a real bracket partner), **certain** (new, only resolves a fill when provable regardless of ordering — can occasionally beat `possible` since deferring lets `running_low` fall further first, so it is *not* a pessimistic-price bound, just a no-guessing one). Island search and cliff-safety rank/filter on `MIN(possible, pessimistic, certain)` (`run_optimization_sweep.ROBUST_ALPHA_SQL`), not `possible` alone, so a node is only selected when it holds up under every resolution. Now loops 14 `stop_loss` values (densified 2026-07-15: `1,2,3,4,5,6,9,12,15,18,21,24,27,30`) x 2 `entry_timing` values through `run_optimization_sweep.py --version v4 --entry-timing <close|open_check> --max-phase <1|2|2.5|3>`, each a phase1→2→2.5(→3) run. Unlike `run_v3_backfill_sweep.sh`, every campaign shares one version string (`v4`) — the real `stop_loss`/`entry_timing` `backtest_cache` columns disambiguate campaigns instead, so island/cliff-safety queries filter on those columns too (`run_optimization_sweep.py::_campaign_scope_sql`). New `sl_sweep_summary` table holds one rollup row per completed campaign for slice/trend queries without re-deriving island stats from raw `backtest_cache`. `--max-phase` (added 2026-07-15) caps a run at the given phase — added after confirming Phase 3 held the best `MIN(possible,pessimistic,certain)` node in 0/30 tagged SOXL+KORU campaigns, and that island/cliff-safety selection only ever reads Phase1+2+2.5 data; `run_phase3_full` now also logs a `Phase3 best=... (pre-Phase3 best=..., IMPROVED/no improvement)` line whenever Phase 3 does run, for live confirmation. New `generation` column (nullable, `Phase2-Island` rows only) records which 1-indexed island-search generation first computed a row. `MAX_PHASE`/`STOP_LOSSES` env vars let the wrapper's single-combo mode (`./scripts/run_v4_backfill_sweep.sh <stop_loss> <close|open_check> [tickers...]`) be scripted — see `scripts/run_backfill_queue.sh` for the ordered multi-step queue (KORU catch-up → SOXL/KORU low-SL density → rest of watchlist → v3-screened non-watchlist tickers), meant to be run directly by the user in their own terminal (tees to `logs/backfill_queue_<timestamp>.log`), not launched by an agent, to avoid `config.json` races with any other in-flight run.
- `scripts/live_sim.py` — manual-step live-sim REPL: drives the real `compute_buy_signal`/`check_sell_condition`/`notify_*` functions against an isolated `cache/trading_sim.db` (via `TRADING_DB_PATH` env override) so the full BUY→placed→filled→arm→trailing-sell Slack sequence can be exercised bar-by-bar without touching the live daemon or `trading_live.db`. `SIM_MODE=1` forces plain-text/typed-input Slack messages (prefixed with a `🧪 SIM MODE`/`🧪 SIM MODE END` header/footer context block, optionally labeled via `SIM_SCENARIO` env var) instead of interactive buttons — the sim never opens its own Socket Mode connection, so real buttons would risk being delivered to the live daemon's connection instead. Real interactive buttons genuinely cannot be tested this way (Slack routes all clicks to whichever process holds the socket, i.e. the live daemon, not the sim) — button *layout* can still be previewed by manually appending a dummy-`action_id` actions block (safe no-op if tapped). `buy`/`sell` REPL commands drive signal checks directly; `pending`/`placed TICKER`/`fill TICKER PRICE`/`remind_buy [--stale]` drive the three-state buy lifecycle (signal → order placed → filled) added 2026-07-10. Interactively tested end-to-end with the user 2026-07-09/10 — found and fixed several real bugs in the process (see `docs/conversation_summary.md`).
- `scripts/sim_delayed_sell.py` (2026-07-17) — repeatable, per-ticker/per-node CLI quantifying the cost of intentionally deferring a same-day exit (SL/trailing-stop/TIME) to the next calendar day, the mirror image of the existing `same_day_block` kernel feature (which defers the entry side after a same-day exit, not the exit side of a same-day entry). Uses `scripts/export_trades.py::simulate_trail_both_deferred_sell`, a pure-Python bar-by-bar mirror of `_simulate_trail_both` (entry logic byte-identical to the existing `simulate_trail_both_annotated`) — not a reimplementation of the exit logic from scratch. Only supports `entry_timing='close'` (no `open_check` branch), so results for an `open_check` node (e.g. GDXD) are indicative, not exact. `.venv/bin/python scripts/sim_delayed_sell.py TICKER --window W --z Z --tb TB --arm ARM --sl SL --ts TS --max-hours H`.
- `scripts/sim_chaos_monkey.py` (2026-07-17) — execution-adherence ("chaos monkey") Monte Carlo: quantifies how much of a node's backtested compounded return depends on catching every entry/exit signal exactly on time, the real risk during manual-execution trading (distinct from island/robust-alpha, which both assume perfect adherence). Uses `scripts/export_trades.py::simulate_trail_both_chaos`/`_resolve_miss`, another pure-Python bar-by-bar mirror of `_simulate_trail_both` (verified byte-identical to `simulate_trail_both_annotated` at `miss_rate=0`). Entry signals are only missable at the two daily signal windows (matching the real Slack cadence); exit triggers (SL/trailing-stop/TIME) are missable every bar (matching continuous live monitoring); TP-arming is never missable (internal state change, not a clickable action). Two modes: `drop` (unbounded per-check miss — the opportunity can vanish for good if the underlying condition stops holding first) and `delay` (same coin flip, but capped at `max_delay_checks` consecutive misses of the same still-true condition before it's forced). Runs all `watchlist_id=9` nodes × both modes × {1,5,10,20}% miss rates × 1000 trials by default, writes `output/chaos_monkey_summary.csv`/`chart.png` (gitignored). `.venv/bin/python scripts/sim_chaos_monkey.py [--tickers T...] [--trials N]`. First real run (2026-07-17): 9/12 tickers lose ~15-31% of mean compounded return at a 20% miss rate (KORU worst, -31%); SOXL/DPST are outliers that hold flat or improve — unexplained, flagged in `docs/backlog_cache.md` for follow-up. `drop` vs `delay` track closely everywhere, suggesting the delay cap rarely binds.
- `scripts/sim_gap_policy.py` (2026-07-19) — decides, empirically, the live-side policy for a trailing-buy entry whose real Open gaps past the trigger price before it can be caught gradually (found while scoping the trailing-buy idle-capital re-sizing item: real gaps exceed `trail_buy_pct` on 19-44% of trading days across the v4 watchlist). Uses `scripts/export_trades.py::simulate_trail_both_gap_policy`, a pure-Python mirror of `_simulate_trail_both` carrying the same gap-through-trigger fix now in the real numba kernel (`backtester.py`, fixed this session — all three resolutions, plus `_simulate_trail_buy`, now fill at the real `Open` when it's already crossed the trigger, instead of the stale theoretical price). `skip_threshold=None` reproduces the corrected kernel's default ("always resize and enter"); a float skips the entry attempt entirely once the gap overshoots the trigger by more than that fraction, so the node waits for the next clean signal instead of chasing. Sweeps `{None, 3%, 5%, 10%, 15%}` per ticker against the real active v4 node (`watchlist_id=57`), writes `output/gap_policy_summary.csv`. `.venv/bin/python scripts/sim_gap_policy.py [--tickers T...] [--watchlist-id N]`. First real run (2026-07-19, all 18 v4 tickers): gap-through trades have consistently low win rates (8.5%-41.8%, most 10-30%) but skipping them moves total compounded return only modestly with no consistent direction per ticker — no universal threshold shows a clear edge, no ticker shows a dramatic blowup avoided by skipping. Leaning "always resize and enter" as the live default (simplest, matches the kernel), pending final confirmation before Part 3 (live order-placement infra) is built.

## Architecture Notes
- Optimization uses `ProcessPoolExecutor` with up to 10 workers
- Results cached in SQLite to avoid re-running completed nodes
- Multi-generation refinement: macro grid scan → frontier detection → fine mesh around top performers
- `active_phase_grid.json` is written by the sweep and read by the Streamlit UI for live progress display
